# 금주노트 — 설계 결정 (첫 버전 · 2026-10-15)

정한 것만 적습니다. 근거 조사(경쟁 앱 · 무작위 시험)는 아직 없습니다 — 다음 리서치 회차에서 `docs/COMPETITORS.md` 로 쌓습니다.

## 0. 시작 페이지 (대표님 요청 2026-10-15)
처음 열면 설정이 아니라 **시작 페이지**(맨 앞 탭 「시작」)가 먼저 나옵니다: 앱이 하는 일 · 3단계 · 시작하기 · 갑자기 끊지 말라는 안전 안내 · 약사·상담자와 함께 보기. 이후에는 오늘 화면으로 열리고 「시작」 탭에서 다시 볼 수 있습니다. 나중에 하위 메뉴로 옮길 수 있게 맨 앞 탭으로 둔 임시 배치입니다.

## 1. 틀
금연노트(SmokeFreeNote)의 틀을 그대로 옮겼습니다: 시작 설정 → 오늘 → 기록 → 통계 → 도움, 하단 탭, 5분 버티기, 내보내기·가져오기, 큰 글씨. 서버가 없고 알림도 아직 없습니다.

## 2. 기록 (`nonalcohol.v1` · `logs[]`)
| 칸 | 값 | 비고 |
|---|---|---|
| `kind` | `drink` 마셨어요 · `urge` 마시고 싶었는데 넘겼어요 | 필수 |
| `cups` | 마신 술의 종류별 단위 수 (1~40, 소주·와인·막걸리·양주는 잔 · 맥주는 캔) | `drink` 일 때만. 합계는 `cups` 를 더하지 않고 `bev` 로 환산한 순수 알코올 g (아래 「저장 형식」 참고) |
| `lv` | 약함 · 보통 · 강함 | 필수 |
| `mood` | 좋음 · 보통 · 나쁨 | 필수 |
| `trig[]` | 퇴근 후 · 식사 중 · 모임·회식 · 스트레스 · 외로움 · 지루함 · 주말 · 기쁜 일 | 여러 개 |
| `cope[]` | 물·차 · 심호흡 · 산책 · 연락하기 · 자리 피하기 · 간식 · 5분 버티기 | `urge` 일 때 |
| `t` | 저장 순간 | 자동 |

- 마신 날도 시도를 끝내지 않습니다. 「목표 다시 정하기」를 눌러야 `attempts[]` 에 `{start, end}` 로 남고 새 시작일을 받습니다.
- **아낀 돈(추정)** = 경과일 × (주당 마신 날 ÷ 7) × 한 번 술값 − (마신 날 수 × 한 번 술값). 음수면 0. 실제 지출이 아니라 설정값 기반 추정이며 화면에도 「추정」으로 적습니다.

## 3. 안전 안내
- 시작 화면 맨 위: 오래 많이 마셨다면 갑자기 끊기 전에 의료진과 상의, 떨림·식은땀·심한 불안·헛것이 보이면 진료·119. (알코올 금단은 위험할 수 있다는 일반 의학 안내)
- 도움 탭: 정신건강위기상담전화 1577-0199(24시간) · 자살예방상담전화 109 · 응급 119. 번호는 2026-10-15 에 검색 결과(서울시 · 쿠키뉴스)로 확인했고 배포 전 재확인이 필요합니다.

## 4. 아직 정하지 않은 것
- 선별 설문(AUDIT-C 등) 도입 여부 — 문구·점수 해석은 교수님 확인 필요
- 「표준잔」·저위험 음주 기준 — 기준 수치 확인 전에는 표시하지 않음
- 알림 기본값(금연노트 3절 참고) — 근거 조사 뒤
- 약사 상담 축 · 약물(날트렉손 등) 복약 칸 — 금연노트 1절 「앱 + 약사 상담」과 맞출지
- 안드로이드 셸 · Health Connect — 금연노트 `docs/NATIVE.md` 참고


## 시안 C·D 반영 (2026-10-15 · 대표님 선택)
- 색: 메디노트 틸로 통일 — `--g4/--g6 #0A7168` · `--g5/--g7 #06413E` (흰 바탕 5.87:1 · 흰 글자/#06413E 11.45:1, WCAG 상대휘도). `--g0`·`--g1` 은 `--d3` 글자 대비(#E1F1EE 에서 4.48:1)가 모자라 그대로 둠.
- 반응형: 폭 700px 이상에서 칸 최대 720px, 기록·통계·함께 보기는 두 칸.
- 「약사·상담자와 함께 보기」는 이제 앱 안 화면(`#v-pro`) — 내 기록에서 바로 요약(기간·당김 수·넘긴 비율·상황·기분) + 이름 없는 요약 CSV(수식 시작 글자 방지) + 전체 백업. 파일을 불러오지 않아 안드로이드 앱 셸에서도 열림.
- 이 화면은 진단·판정을 하지 않는다. 리서치 세션 내용은 아직 반영하지 않음(원문 확인 후).

## 갈망 0~10 · 표준잔 · 상담센터 (2026-10-15 · 대표님 요청)
- 갈망: 기록 화면의 「얼마나 당겼나요」를 0~10 숫자(0 = 전혀 · 10 = 가장 심함)로. 예전 3단계(`lv`)는 목록·팁·옛 기록과 맞추려고 0~3 약함 · 4~6 보통 · 7~10 강함 으로 같이 남긴다. 저장 필드 `cr`(0~10 정수 또는 null) 추가.
- 표준잔: 마신 기록에 술 종류(소주·맥주·와인·막걸리·양주)와 잔 수. 순수 알코올 g = ml × 도수% × 0.789 (대표 분량: 소주 50ml 17% · 맥주 355ml 4.5% · 와인 150ml 12% · 막걸리 200ml 6% · 양주 30ml 40%). **대략적인 계산값이며 음주 기준·권고량이 아니다** — 한국의 표준잔 g 기준은 출처를 확인하지 못해 앱에 박지 않았다. 저장 필드 `bev` 추가.
- 요약·CSV: 평균 갈망, 최근 7일 순수 알코올(대략), 술 종류·잔 수·알코올 g 열 추가.
- 상담센터: 도움 탭 「가까운 상담센터 찾기」 — 지도 검색 링크(누를 때만 열림, 앱이 주소를 갖고 있지 않다). 안내 문구는 「상담은 해당 기관의 전문 인력이 해요. 이 앱은 연결만 도와요」 — 약사·전공의 등 특정 직역이 상담한다고 쓰지 않는다(법령 확인 전).

### 저장 형식 (로그 한 줄) — 위 절 기준 최신
`{v, t, kind: "urge"|"drink", cups, bev, cr, lv, mood, trig[], cope[]}`
- `cups`: 마신 기록의 **종류별 단위 수**(소주·와인·막걸리·양주는 잔, 맥주는 캔). 서로 다른 종류의 `cups` 는 더하지 않고 순수 알코올 g 로 합친다.
- `bev`: 술 종류(없으면 예전 기록 → 합계에서 「이상/모름」으로 따로 센다).
- `cr`: 갈망 0~10 정수 또는 null(예전 기록·5분 버티기 완료 기록은 점수를 지어내지 않고 null). `lv`: 예전 3단계(없는 `cr` 이면 이것이 유일한 세기 값 — CSV 의 「세기(예전 3단계)」 열).

## 데이터베이스(.db) (2026-10-15 · 대표님 요청)
- `nadb.js` + `vendor/sql-wasm.*` (sql.js 1.12.0 · MIT) — 기록으로 SQLite 데이터베이스를 만들어 읽고 쓴다. 기록의 원본은 그대로 localStorage(`nonalcohol.v1`)이고, `.db` 는 저장할 때마다 낡음 표시(`invalidate`)가 되어 필요할 때 다시 만들어진다. 서버로 가지 않는다.
- 표: `meta(k,v)` · `logs(id,t,kind,cups,bev,cr,lv,mood)` · `log_items(log_id,field,pos,value)` (목록 필드 trig·cope 를 한 줄씩 — Room 의 1:N 과 같은 모양) · 뷰 `logs_flat` (목록 필드를 「 / 」로 이어 붙임). `PRAGMA user_version = 1`.
- 읽기: `NADB.query(sql)`(SELECT 만) · `NADB.table(el, sql)` · HTML 에서 `<b data-db="SELECT COUNT(*) || '건' FROM logs">` / `<ul data-db-list="SELECT …">` — 값은 글자로만 넣는다.
- 쓰기: `.db` 내보내기 / 가져오기(합치기). 가져온 파일은 `meta.app = 'nonalcohol'` 확인 뒤 정해진 칸만 SELECT 하고 `cleanLog` + 선택지 허용 목록으로 걸러 넣는다 (최대 20MB · 5000건).
- 앱 셸(`window.Native`)에는 파일 내려받기·선택기가 없어 내보내기·가져오기 단추를 숨긴다.

## 메인(홈) 화면 (2026-10-15 · 대표님 요청)
앱을 열면 첫 화면이 「메인」입니다 — 오늘 기록 여부(○/✓), 최근 기록 3건, 기록·통계·상담·도움으로 가는 바로가기. 기록이 없는 날에도 같은 화면이 뜹니다.
- 새 색·글자 크기는 만들지 않았습니다 (기존 토큰).
- 진단·위험 판정 문구는 쓰지 않고, 있는 기록만 보여 줍니다.

## 여러 탭에서 저장이 서로 덮어쓰지 않게 (2026-10-15 · 대표님 요청)
탭 두 개를 열어 두고 쓰면, 오래 열려 있던 탭이 저장할 때 다른 탭이 방금 저장한 기록을 낡은 상태로 덮어썼습니다.
- 저장하기 직전에 지금 저장된 것을 다시 읽어, 「마지막으로 본 저장본 · 내 상태 · 지금 저장된 것」 셋을 합칩니다. 내가 지운 기록은 빼고, 내가 새로 넣은 기록은 넣고, 다른 탭이 넣은 기록은 지킵니다.
- 다른 탭이 저장하면 `storage` 이벤트로 바로 합쳐 보여 줍니다(기록·통계·메인). 탭이 다시 보일 때도 한 번 확인합니다. `.db` 는 합쳐진 기록으로 다시 만들어집니다.
- 저장 형식은 바뀌지 않습니다.
